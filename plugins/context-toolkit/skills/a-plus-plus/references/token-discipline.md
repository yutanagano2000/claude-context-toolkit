# トークン規律（無人実行前提）

このゴールの実行中、ユーザーは画面を見ていません。人向けの表示は成果ではなく費用です。
コーディング品質は落とさず、出力と読み込みだけを削ること:
- 文体は caveman ultra（`context-toolkit:caveman` args=`ultra`）を全ターン維持する
- 進捗報告・計画の宣言・ツール呼び出しの予告と事後報告を書かない。
  次の行動があるなら、書かずに実行する。テキストは（a）ユーザー承認が要る分岐、
  （b）破壊的操作の警告、（c）最終報告 — の3つだけ
- 証拠は**画面に貼らず、ファイルに落としてパスで示す**。テスト・ビルド・ベンチの出力は
  `> logs/<name>.log 2>&1` に書き、報告は「パス + 1行の判定 + 決定的な1行の引用」だけ。
  ログ全文・成功した長い出力を会話に貼るのは禁止
- 読み込みは狭く。20KB 超のファイルは Grep -n でアンカーを取ってから offset/limit で
  該当宣言だけ読む（宣言の途中で切らない）。編集直後のファイルを読み直さない
- 出力を加工するつもりの実行（絞り込み・件数・集計・パース）は素の Bash でなく
  `ctx_batch_execute` / `ctx_execute` に通し、生バイトはサンドボックスに残して
  結論だけを持ち帰る。素の Bash は短い固定出力の観測と状態変更（git/mkdir/mv）に限る
- Bash は 1 呼び出し 1 出力コマンド。`| head` / `| tail` で手切りしない（rtk の
  フィルタが無効化される）。`git diff` の前に `--stat`、スイートの前に単一テスト、
  ビルドログの前に終了コード
- 独立したツール呼び出しは 1 メッセージにまとめて並列で撃つ（ターンごとに会話全体が
  再送されるため、往復回数がそのままコストになる）
- 広い「どこにあるか」探索はサブエージェントに投げ、file:line だけ返させる。
  ただし実装はサブエージェントの要約でなく自分で読んだ実バイトに対して行う
- 節約は品質より優先しない。診断中のエラー本文・これから編集するバイト・呼び出す
  シグネチャは絶対に省略しない（ここを削ると往復が増えて逆に高くつく）
